# Character Identity and Spell Adaptation

核对日期：2026-09-06。本文保留 alpha-0.0.7 时的资料核对与改造依据。alpha-0.0.8 已按其边界实现角色独立能力池、御札追踪/驻留封魔阵、星弹/持续魔炮与独立符卡效果；下面的旧版根因表是历史基线，不代表这些问题仍全部存在。当前实际规则见 docs/rebirth_design.md，交付验证见 docs/rebirth_validation.md。

本轮核对当前实际可玩的博丽灵梦、雾雨魔理沙。以下为有出处的代表性符卡与能力，不声称穷尽两人历代全部符卡，更不声称已经核查旧库存中的所有角色。

## 1. 已确认的创作边界

- 东方人物的身份、能力、道具和符卡语言是设计依据；武侠是风格与内核，不能成为给每个人强加剑、雷法和修仙等级的理由。
- 保留人物辨识度，不是把人物限制为一种武器。灵梦不只是符纸，魔理沙也不只有一束魔炮；扩展必须有具体来源，而不是凭印象套流派。
- 本作可以调整原作符卡的触发、节奏、范围和数值，以适配幸存者玩法；必须标明这是本作转译，不能冒充原作逐帧复刻。
- 不仅改名字和颜色：发射方式、弹道、命中方式、有效距离、成长选择和战斗节奏都要共同支撑角色身份。

## 2. 核对结果：博丽灵梦

### 资料依据

- 《东方红魔乡》说明书明确其武器为符纸和阴阳玉；《东方永夜抄》说明书也保留这一设定。[S1][S2]
- THBWiki 符卡条目记录：灵符「梦想封印」、梦符「封魔阵」在《红魔乡》中分别属于灵梦不同自机配置的 Bomb；梦符「二重结界」在《妖妖梦》中作为其梦符配置低速 Bomb 登场，也在《永夜抄》中作为 Boss 符卡出现。[S4][S5][S6]
- 《The Grimoire of Marisa》的灵梦篇还提供了封魔、结界与「梦想天生」等具体法术资料。它支持灵梦的空间/结界表达，不支持把她默认改造成飞剑角色。[S9]

### 建议的本作转译，不是原作性能宣称

| 层次 | 候选表达 | 与当前版本的实质区别 |
| --- | --- | --- |
| 常规攻击 | 自动发射的御札/符纸，以追踪或覆盖方向的差异提供成长选择 | 不能把现有剑形直线弹换贴图就称为完成；应明确索敌、转向、命中与散布规则 |
| 护身与控场 | 阴阳玉，以及有持续范围与位置取舍的封魔阵/结界 | 不把不同符卡全混成一个泛称的“阴阳阵”；几何形态和生效方式需要可辨识 |
| 标志性符卡 | 优先以灵符「梦想封印」为一条代表性能力，随后再考虑结界分支 | 从来源定义效果与表现，不沿用全角色相同的“剑意爆发” |
| 操作气质 | 从容走位、掌握间距、以结界与覆盖处理妖群 | 武侠意味来自进退与空间判断，不来自强行持剑 |

这里的追踪取舍、范围持续时间、自动触发等均为设计候选；需要实现与试玩验证，不是引用原作说明书中的数值结论。

## 3. 核对结果：雾雨魔理沙

### 资料依据

- 《东方求闻史纪》记载她擅长光与热的魔法，重视火力；《永夜抄》说明书列有星尘导弹类普通射击，以及恋符「Master Spark」、魔炮「Final Spark」。不能把那一作同队爱丽丝的人偶射击全部算到魔理沙身上。[S2][S3]
- THBWiki 的魔符「Stardust Reverie」（星尘幻想）与恋符「Master Spark」（极限火花）条目都列出《红魔乡》自机 Bomb 的出处；魔符「Milky Way」（银河）条目列出《妖妖梦》等作品的登场。[S7][S8][S10]
- 《The Grimoire of Marisa》对「Milky Way」描述了周围星屑的运用，对「Master Spark」说明了迷你八卦炉发出的激光与高火力、破绽的关系。这是星光/光束体系的资料基础，而不是当前版本跳跃雷链的依据。[S11]
- 符卡前缀要核实：这里的 Stardust Reverie 与 Milky Way 是“魔符”，不能因为内容有星星就擅自写成“星符”。中文别译可辅助展示，原名与出处用于避免混淆。

### 建议的本作转译，不是原作性能宣称

| 层次 | 候选表达 | 与当前版本的实质区别 |
| --- | --- | --- |
| 常规攻击 | 星形魔弹、星尘散布或集中射击 | 用覆盖宽度、弹量与集中度形成选择，不再让魔理沙以御剑起步 |
| 标志性能力 | 基于 Master Spark 的持续光束/魔炮 | 必须具有方向、持续时间与光束命中几何；雷链换名字不是魔炮 |
| 成长方向 | 星屑覆盖与集中火力之间的取舍 | 不再让强度只表现为“连锁目标更多” |
| 操作气质 | 为火力寻找角度，抓住输出窗口，再转移位置 | 武侠意味来自蓄势、出手和收势，不要求魔理沙改学雷法 |

自动寻找目标、前摇提示、发射时有限转向等是适配本作的候选方案，不代表各原作的 Master Spark 都具有这些属性。是否采用以及具体数值须另做体验验证；不因此新增强制主动施法按键。

## 4. alpha-0.0.7 的根因与待修改范围

| 当前证据 | 问题 | 正确的修改层次 |
| --- | --- | --- |
| `game/core/RunState.cs` 为所有角色初始化 Sword，魔理沙再初始化 Lightning | 人物差异被套进固定剑/雷武器槽 | 角色定义决定初始能力，而不是所有人共用一套默认武器 |
| `game/core/RunProgression.cs` 从 ArtCatalog.All 生成同一候选池 | 即便只修初始装备，升级也会重新混回不合适的攻击 | 角色能力池和公共成长分开；必须在候选生成层保证边界 |
| `game/core/RunWeapons.cs` 的飞剑、跳跃雷链与公共爆发 | 行为本身错位，非单纯命名问题 | 重写角色所需的御札/星弹/光束行为；底层碰撞等可合理共用 |
| `game/presentation/CombatDrawing.cs` 与其他表现文件 | 轮廓、轨迹、爆发缺少人物语汇 | 效果、判定、声音与人物攻击同步变化，不能只换颜色 |
| `game/presentation/MenuScreens.cs`、构筑页、HUD 与说明文案 | 把现有错误规则包装成角色设定 | 显示正确来源与本作效果，清除强加的御剑/雷法定位 |
| 标题与统一“剑意”表达 | 用全局剑客语汇限制非剑术人物 | 一并审视是否保留；本轮不擅自改名，也不把改名当成机制修复 |

旧 `content/base/pack.json` 已有梦想封印与 Master Spark 名称，说明资料并非完全缺失；但旧清单存在不等于新版已经接入，更不能用它代替当前运行时审查。

## 5. 武侠内核的落点（设计建议）

- 人物如何行事、如何面对异变与他人，提供叙事上的江湖气；不是把现有身份全部替换成门派弟子。
- 通过进退、距离、蓄势与破绽塑造战斗节奏，保留移动和构筑为主的操作方式。
- 构筑提供招式关系与取舍，而不是给所有攻击加上“诀、经、九重天”即算武侠。
- 东方的符卡规则与人物关系仍是世界依据；武侠化表达不能反过来覆盖这些设定。

## 6. 后续实现的验收边界

1. 每位可玩角色先有资料卡：身份、代表能力、符卡原名、来源作品、资料出处、本作改编说明。
2. 灵梦与魔理沙的起始攻击、候选能力和代表性符卡应可辨识；无依据的跨角色能力不能通过共用随机池自动混入。
3. 不能用改名字、改颜色、仅改伤害倍率满足人物差异验收；至少检查弹道、命中方式与局内选择。
4. 保留已改善的 E 查看、暂停/返回、音量与历史日志，不因人物纠偏再次丢失基础可用性。
5. 自动测试覆盖角色初始能力、候选池隔离、效果边界与构筑说明一致性；视觉检查确认符札、星弹与魔炮不会重新表现成飞剑或雷链。
6. 只有代码、实际渲染与独立 EXE 都验证后，才发布新的版本并追加日志。当前 alpha-0.0.7 没有被覆盖，其人物问题也没有因本文而解决。
