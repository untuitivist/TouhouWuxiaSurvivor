# Sprite Drawing Study

研究日期：2026-09-09。用途：纠正本项目人物精灵的制作方法，不是新美术交付或教程画风替换。

## 1. 先纠正制作方法

- 使用 Aseprite、拥有很多图层、逐像素复写、RGBA 一致，均不能证明人体、像素表达和动画已经画好。
- 先前坐标拼形试稿没有忠实保留用户参考；最新 native-v01 则是脚本复写参考像素。两者都不能代替用户要求的 Aseprite 临摹重绘。
- 原图复写可以用于对照，但不能用自动描摹的笔数、运行时间、颜色一致性冒充美术进展。
- 本轮只研究、检查和记录；没有制作通过验收的新人物、完成动画或修改游戏视角。

## 3. 不变的项目要求

- 忠实保留已认可的灵梦、魔理沙设定板；不另造脸、头身比、帽型、袖口、衣褶、鞋靴或色板。原图位置见 `art/reference/gameplay_reference_manifest.json`。
- 立绘与局内精灵分别制作。局内精灵以参考板自己的小人物为对照，不直接缩小大立绘，也不把教程范例的 16×16 或固定帧数当成项目标准。
- 武侠体现在已有参考的利落行装、进退姿态和动作气质，不以换武器抹掉人物身份。灵梦保持御札发射、阴阳玉环身、阵在地面；魔理沙保持星光、八卦炉与魔炮。
- 保留 C# 单项目 Windows/Web、现有成长、数值、操作与性能边界。本次没有授权新能力或发布。

## 4. 下一张样板的制作顺序

### A. 校准身体，不急着画花纹

1. 在 Aseprite 隐藏锁定参考层，另建结构辅助层与实际绘制层。源文件使用新编号，不覆盖用户手改。
2. 在参考原始尺度标出头顶、下颌、肩、胸腔、骨盆、肘、手、膝和脚底；记录的是参考的相对关系，不套一个新的头身比。
3. 用清楚的体块确认肩胯朝向、手臂连接、膝弯和重心。必须能解释袖子里手臂的去向，不能用宽袖盖住断开的身体。
4. 临摹外轮廓与主要遮挡关系。先核对同尺寸外形，再按参考补头发、衣料和饰品；教学用结构层默认不导出。

### B. 用像素簇表达细节

1. 从参考中确认光源和明暗体块，让亮面、转折面、暗面服务于头发、布料和肢体，而不是均匀铺高光。
2. 检查斜线的台阶、无意孤立像素、袖口与手部粘连、腿与衣摆粘连。去除的只能是本次绘制错误，不能以“清理”为由简化用户认可的设计。
3. 先在 1× 查看辨识度，再用整数倍最近邻放大检查边缘。放大图好看不能代替游戏尺度读得清；不靠滤镜、批量减色或模糊修边。
4. 透明素材在浅、中、深底色和实际游戏背景中分别检查；不能用冷色阈值一刀切删除背景，因为衣物、头发和阴影也可能含同类颜色。

### C. 静态姿势成立后才做动作

1. 先比较正、侧、背姿势中的体量、头饰位置和身体高度。辫子、八卦炉、持物手等非对称细节不自动镜像。
2. 按行走的接触、承重、经过和迈出阶段制作关键姿势，再按实际动作决定补帧和时长；不承诺某个固定帧数天然更好。
3. 统一帧画布和地面参考点，但不把脚、头或身体强行钉死。应检查支撑脚的合理运动、重心转移，以及身体上下起伏是否连续。
4. 用洋葱皮查相邻帧体量漂移，再循环播放查节奏和脚滑；衣摆、袖子、头发是跟随身体的次级运动，不是替代身体的晃动。
5. 施法按人物身份设计蓄势、释放、回收：灵梦的御札手势和魔理沙的八卦炉朝向分别处理。特效层不能遮住动作问题。

## 5. 源文件与验收

- 按实际遮挡分层，例如后侧头发／后侧袖子、身体衣装、脸与前发、前侧手袖、腿靴、头饰、持物及独立特效。按横纵坐标切成数层不能自动叫作合理解剖分层。
- 每次修改交付可编辑 `.aseprite`、同尺寸静态对照和真实时间轴动画预览；明确哪些像素是脚本处理、哪些是新增绘制。自动步骤不得称为人工手绘。
- 外形门槛：参考的造型与人体关系保留，没有擅自改脸、帽型、衣装或比例。
- 动作门槛：方向一致，支撑关系和步态说得通，非对称物件无跳边，循环衔接与帧时长经播放检查。
- 使用门槛：透明边无残留或缺口，参考／结构层不参与导出，源文件重开可编辑，游戏尺度能读清。
- 美术审查与技术校验分开记录。先完成并审查一张局内姿势样板；没有过关就不批量生成全角色，也不接入运行时或改视角。

## 6. 当前产物的真实状态

`art/trace/native-v01/` 保存两位角色各一张完整参考板、一张透明立绘和十二张动作单帧，共 28 份自动复描源文件。参考板内的“实机演出”仍是参考图内容，不是当前游戏截图。

原生画笔复写保留了选中像素的颜色与位置，但透明选择仍有场景残片和边界风险；单帧也没有组成或验证真实动画。完整板像素一致仅证明参考复现，透明图与同一个遮罩一致不能证明遮罩正确。详见该目录 README；全部保持 `runtime_eligible=false`。
