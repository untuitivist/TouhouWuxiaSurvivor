# ECS 分层约定

本项目采用混合架构，不把所有 Godot 节点机械地改成 ECS。

## 保留面向对象的部分

- 主菜单、暂停菜单、设置、图鉴和死亡结算等低频界面。
- 无限地图的区块生成、群系定义、结构定义和内容包配置。
- 玩家主体、局外成长、符卡定义和音频控制等低数量协调对象。
- 需要编辑器场景、信号和明确生命周期的视觉控制器。

## 使用 ECS 的部分

- 运行中数量随时间增长的敌人、子弹、经验灵息和普通掉落物。
- 位置、速度、生命、伤害、寿命、目标等高频变化数据。
- 移动、索敌、自动射击、命中、吸附、回收和刷怪等批量系统。

## 迁移顺序

1. 投射物：组件池、移动系统、命中系统和批量绘制已接入 `WorldDemo`。
2. 敌人：先把追踪、生命和接触伤害迁移到数据系统，保留视觉桥接。
3. 灵息与掉落物：迁移吸附、拾取和寿命，统一进入批量回收。
4. 运行时视觉：在数据稳定后使用共享绘制或对象池，避免重新引入逐实体节点。

## 约束

- 每个组件、系统和桥接类单独文件，代码主体控制在 250 行以内。
- ECS 系统只读取和修改组件，不依赖 UI、地图生成器或内容包服务。
- 内容包只提供定义数据；实体数量和行为由运行时系统决定。
- 迁移阶段保留旧 OOP 场景作为回退路径，测试通过后再移除旧路径。
