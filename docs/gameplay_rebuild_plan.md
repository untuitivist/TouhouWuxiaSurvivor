# 下一阶段：以构筑乐趣驱动解耦

> 后续讨论（2026-09-12）：用户提出长流程、有限选择，并明确现阶段不支持多个完整主线兼修。新方案见[单主线成长设计](run_growth_design.md)，目前只是讨论稿，未实施。下文保留 2026-09-08 的历史状态；相容技法仍保留，新稿只提议对关键定式做取舍，不把旧兼修规则改写成从未存在。

## 状态与用户确认（2026-09-08）

用户反馈 alpha-0.1.4 已经不卡，要求下一步做到“好玩、解耦、继承重建前的思想”。因此性能暂退为回归底线，不再把新增性能改造当成主线。这是用户当前设备的体验反馈，不扩写为所有移动设备已通过验收。

本文件是下一轮改造方案，不代表下列机制已经实现。本次只审阅旧设计、核对现状和固定方向；不改战斗数值、玩法源码、存档或发布版本，不推送部署。

## 旧设计真正值得继承的部分

参考 docs/plugin_first_design.md、docs/combat_balance.md，以及 src/gameplay/progression 中的定义与候选逻辑。旧文档中的迁移目标与已经实现的代码必须区分，旧数值和旧代码不直接成为新版本基准。

| 思想 | 保留的玩家价值 | 新版的处理方式 |
| --- | --- | --- |
| 横向构筑 | 同一角色有不同打法，不只是早晚点满同一套能力 | 恢复行为特化、前置与组合关系；保留角色能力身份 |
| 亲和倾向 | 已选路线可以继续成长，同时留出探索与补缺机会 | 前置过滤后按路线标签生成候选，保持无放回和固定种子复现，不把倾向做成锁死路线 |
| 内容横向扩展 | 本体完整，新内容提供另一种选择而不是数值上位 | 作品身份不增加强度或候选类别总权重，不先搬全量作品库存 |
| 一套权威定义 | 玩家看到的说明与真正生效的行为一致 | 升级页、E 构筑页、图鉴和战斗读取共享解析结果 |
| 规则与内容分离 | 新内容可扩展、可独立验证 | 保留四层边界思想，不先造热加载 DLL、反射框架或运行中内容切换 |
| 探索和无尽 | 地图目标影响行程，成型构筑有继续游玩的空间 | 在有限一局和构筑成立后分轮评估，不把扩大地图当作更好玩 |

旧版运行基线允许特化兼修，不默认恢复为互斥技能树。旧代码虽然有排除关系字段，不能据此认定原规则要求强制二选一。旧版统一武学名称与能力模板也不照搬给东方人物。

## 当前问题：证据与推断分开

1. game/core/RunProgression.cs 的 OfferChoices 只按角色与重数上限过滤，再从候选中随机抽取；没有前置、亲和或行为特化选择。
2. game/core/ArtCatalog.cs 中每人三种五重术式和四类三重公共修习；大多数升级改变弹数、伤害、范围或频率。候选没有最终构筑容量限制，足够升级后可以全部点满。由此推断单局差别容易退化为获得顺序，而非保留到终局的打法差别；是否构成实际体验问题仍需试玩。
3. RunState 使用多个 partial 文件，但仍拥有移动、升级、遭遇、符卡、净化和胜负等逻辑。分文件不等于依赖已经隔离。
4. JournalCatalog 为获取角色和敌人基准，会创建临时 RunState 并调用 SpawnEnemy。它没有改动当前战斗，但说明只读定义与运行状态尚未真正分开。
5. 角色数值、能力身份、素材映射仍有多处枚举判断。第一步应解开即将改变的构筑链路，而不是同时重写全部系统。

## 第一轮可玩交付：同一角色的不同路线

先服务现有灵梦、魔理沙和有限一局，不先增加角色、地图面积或大量技能数量。

### 用户补充：基础攻击、能力解锁、行为升级

用户进一步明确：开局只有基础攻击，其他能力通过升级获得，再围绕各能力选择多种行为升级。这比“开局已有成熟能力，之后选择特化”更明确，优先于前一轮方案中的笼统表述。

灵梦示意结构（用户以此举例，不代表分支已定稿或已实现）：

```text
符：开局基础攻击
├─ 追踪符：改变飞行/索敌行为
├─ 爆炸符：增加命中后的范围效果
└─ 其他符类升级

阵：需要先解锁
├─ 在敌怪聚集处出现：改变施放位置选择
├─ 禁锢：增加控制效果
└─ 其他阵类升级

阴阳玉：需要先解锁
├─ 消弹：增加与敌弹交互的效果
├─ 蓄力发射：增加积蓄与释放行为
└─ 其他阴阳玉升级
```

- “低怪聚集处”结合语音上下文按“敌怪聚集处”理解；用户说“打个比方”，这些例子确定结构，不自动确定数值、命名、全部候选或原作符卡出处。
- 基础符不预先包含后续的追踪/爆炸升级；自动攻击和按键习惯保留。阵与阴阳玉未解锁时不生效，不出现它们的后续升级选项。
- 同样的单一基础攻击原则适用于魔理沙：以基础星弹起步，魔炮等附加攻击不再开局赠送。现有满蓄势自动符卡也需纳入解锁设计，不能绕过“只有基础攻击”的原则；具体解锁前置仍待设计。
- 升级可以横向取得新能力，也可以纵向改变已解锁能力；不把解锁与后续升级塞成同一种“重数 +1”。
- 分支之间的兼修、互斥、覆盖关系尚未由这些例子确定。沿用“不默认强制互斥”的边界；若允许追踪与爆炸兼修，应由两个行为组合生效，不另写一套重复的“追踪爆炸符”系统。
- “蓄力发射”先按既有自动战斗约束设计，不因此擅自增加必须频繁操作的新按键；消弹范围/次数、蓄力时序、禁锢规则与敌群选点均需独立验证。

- 从现有能力发展少量行为特化：灵梦优先验证追踪游走与驻留控场的差别；魔理沙优先验证星屑覆盖与魔炮火线经营的差别。这些是玩法假设，不是已经承诺的最终新符卡或原作设定。
- 特化必须改变走位、覆盖、目标选择或风险窗口中的至少一项；只把伤害系数加大不算新路线。
- 恢复明确前置和轻度亲和：选项解释“为什么出现、还缺什么、选择后改变什么”；保留偏离既有路线的机会。
- 根据正常单局的升级供给与前置深度形成实际取舍，不默认强制互斥，也不通过删掉关键能力制造选择。需要调整成长节奏或增加容量限制时，先单独验证并说明。
- 新构筑必须在三选一、E 页与图鉴中同步解释，不能先实现战斗分支，之后再手工补一套说明。
- 保留现有键位、触屏操作、慢移、闪身和暂停规则；不增加必须频繁按下的主动攻击键。武侠体现在修习、进退、距离与取舍，不替换东方角色原本的能力。

## 与玩法同时落地的解耦范围

### 1. 定义与运行状态分开

先建立有稳定 ID 的角色、能力和升级节点定义。初始属性、前置、路线标签和效果描述属于定义；本局等级、所选节点、冷却与蓄势属于状态。图鉴读取定义投影，不再为查看数值启动临时战斗。

升级节点明确区分“解锁能力”“添加/改变行为”“数值强化”。能力解锁关系不依赖中文名或数组位置；选点策略、飞行行为、命中效果和敌弹交互分开表达，避免为每种分支组合复制完整技能。不同角色的专属行为仍保留独立实现。

作者使用稳定内容 ID，战斗热路径仍可在开局解析为紧凑索引；不要求每个实体每帧查字符串字典。

### 2. 候选规则与应用效果分开

候选服务只负责过滤、权重与无放回抽样；构筑解析负责把选择变成可读参数和行为配置；运行系统执行行为。RunState 保留本局协调，不继续吸收所有新增特化分支。

角色行为不强行合成一种“万能攻击”：御札追踪、驻留阵地、星弹和锁向魔炮保留不同执行能力；内容使用明确契约组合这些能力。

### 3. 表现只消费结果

Windows/Web 共用同一套定义、规则和行为。UI 发送选择命令、读取只读视图；绘制读取战斗快照或领域事件，不自己计算升级效果。继续使用高频批量系统与低频 OOP 编排，不为“全部插件化”制造每颗弹丸的对象层。

### 4. 开局冻结

内容配置和规则在开局校验并冻结，同一输入与种子仍可复现。运行中不扫描素材目录、解析内容 JSON 或替换规则。首轮可先用编译内定义，不急着建设完整外部包加载器。

## 后续顺序

1. 构筑与候选改造：先让同一角色有值得重开的不同路线。
2. 遭遇与可选目标：用敌人职责和局面差异检验路线，不只增加血量、密度或缩短刷新间隔；再评估古印和探索目标是否值得设计不同奖励。
3. 终局与无尽：Boss 检验构筑的强弱项；成型路线是否值得继续玩，再决定无尽回归方式。
4. 内容包：用一份可关闭的横向内容验证契约，不一次搬回全部旧作品。

不在本轮承诺恢复旧 4 主攻 + 2 护持槽位、旧动态压力公式、无限地图、永久数值养成或全作品目录；继承其目的，不自动继承所有规则与数值。

## 验收：好玩与解耦各自有证据

- 开局只启用一种基础攻击；未解锁的阵、阴阳玉、魔炮或其他附加攻击不产生战斗效果。
- 未取得能力时，其后续行为升级不进入候选；取得能力后才按对应前置开放升级。横向解锁和纵向成长都应有正常获得机会。
- 每个行为升级在实际战斗中可辨，兼修/覆盖规则与 UI 一致；不能只有卡片文字变化或偷偷自动赠送子节点。

- 同一角色至少能形成两条在操作策略上可辨的路线；同种子对照不同选择，记录路线成型时点、选择内容、近敌时间、受击和清场情况。
- 有限一局结束前不应普遍回到同一套满级配置；如果特化只是必选项或看不出区别，就修改而不是继续添加数量。
- 亲和不能阻断补缺；前置不足、已满级、非法归属不进入可选池。固定种子、候选无重复、效果描述一致、暂停与连续升级冻结均有回归。
- 纯结构迁移阶段先证明旧行为不变，再单独评估玩法变化，避免同时改结构与数值后无法归因。
- 增加一个已有行为支持的升级节点，不需要同时修改角色选择页、三选一算法、图鉴和平台代码；新增行为在其系统内实现并独立测试。
- 自动化证明正确性和基本可行性，不能代替用户试玩证明“好玩”。两端性能保持当前基线，不以减少敌人或改变预算掩盖结构回退。
