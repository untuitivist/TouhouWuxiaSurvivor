# 插件优先的产品与架构基调

## 一句话定义

本项目的主基调是：**内核只提供规则和运行环境，一切具体内容都由插件注册。**

幻想乡本体是一份始终启用、随游戏发行的基础插件；东方红魔乡是第一份可关闭的参考插件。
本体必须独立构成完整游戏，红魔乡只横向增加选择，不能替本体补齐缺失流程，也不能提供更高的
数值上限。

## “一切皆插件”的准确含义

这里的插件是具有稳定身份、明确所有权、统一注册契约和独立验收的模块，不等于让每个类都成为
可热加载 DLL。

- 地区、结构、敌人、角色、Build、奥义、Boss 招式、素材、音频和本地化都由所属插件提供。
- 菜单、图鉴、地图、升级选择和状态页只读取注册后的统一视图，不按作品编号写分支。
- 高频 ECS 系统在开局前完成装配并冻结，战斗过程中不扫描目录、不使用反射，也不动态卸载插件。
- 低频界面和遭遇编排可以通过接口组合，但同样只能依赖契约，不能向具体作品反向取数据。
- 插件化的目标是隔离变化、保证横向扩展和便于测试，不是增加抽象层数量。

## 三层边界

### 1. Kernel：游戏内核

内核拥有机制，不拥有东方内容：

- 游戏生命周期、输入、暂停、存档、随机种子和场景切换。
- ECS 存储、调度、碰撞、投射物预算和渲染提交。
- 无限世界坐标、区块流送、地图发现和结构实例生命周期。
- 插件发现、版本校验、依赖解析、注册表冻结和错误报告。
- 通用 UI 容器、音频总线、资源加载、图鉴投影和调试指标。

内核只负责调用“压力策略”“升级候选策略”“胜负策略”等契约，不定义五分钟、`K/S`、经验需求
或三选一权重。这些默认规则由 Base Plugin 注册，未来可以由另一种游戏模式整体替换。

内核中禁止出现 `th06_eosd`、蕾米莉亚、红魔馆等内容身份，也禁止按作品编号维护 `switch`。

### 2. Base Plugin：幻想乡本体

本体使用与可选插件相同的注册契约，但始终启用且不可在新局菜单中关闭。它提供一局游戏所需的
最小完整内容，而不是“公共素材垃圾桶”或 DLC 缺项的回退层。

本体可以公开少量稳定能力标签，例如普通攻击、中心弹幕、护身、聚灵和结构遭遇，供可选插件声明
协同；可选插件不能直接引用本体内部类、场景路径或中文显示名。

本体同时拥有默认 Run Mode：五分钟目标、动态压力换档、经验升级、三选一、Boss 胜负与无尽延续。
这些规则属于一组原子配置，作品插件不能逐项篡改。

### 3. Optional Plugin：作品插件

每个作品插件彼此平行，只依赖内核契约和本体公开能力，不依赖另一个可选作品。

- 启用插件只增加候选和世界可能性，不修改全局经验、刷新、槽位或基础属性公式。
- 禁用插件后，其地区、结构、敌人、角色、奥义、Boss、素材和图鉴条目必须全部消失。
- 插件缺少某类内容时必须显式声明不可用，不能静默借用另一个作品并伪装成本作素材。
- 跨作复用必须记录来源、原因和审核状态；运行时身份仍属于消费方插件。

## 依赖方向

```text
Game Host
  -> Kernel Contracts
       <- Base Plugin
       <- TH06 Plugin
       <- Future Optional Plugins
```

允许的依赖只有指向契约。内核不依赖插件，可选插件之间不互相依赖，Base 不知道有哪些可选插件。
角色、奥义或素材之间的关联使用稳定 ID 和能力标签解析，不使用中文名称连接对象。

## 插件拥有的完整内容面

一份插件不是单个 `pack.json`，而是以下内容的逻辑所有者：

| 领域 | 插件必须拥有的定义 |
| --- | --- |
| 身份 | 插件 ID、版本、依赖、兼容版本、显示名称、选择状态 |
| 规则 | Run Mode、压力策略、升级策略、掉落策略、胜负与无尽规则 |
| 世界 | 地区、地貌规则、结构模板、放置规则、发现与遭遇 |
| 战斗 | 普通敌人、强度档、AI 档案、掉落、Boss 档案与招式 |
| 角色 | 稳定角色 ID、自机档案、Boss 档案、起始倾向 |
| Build | 升级节点、重数上限、行为变化、亲和、奥义和协同标签 |
| 表现 | 纹理、弹幕图集、动画、音频、地图颜色和 UI 文本 |
| 兼容 | 存档迁移、缺失插件说明、素材来源和许可边界 |
| 验收 | 清单完整性、隔离、数值预算、真实运行和视觉测试 |

当前仓库把这些所有权分散在 `content`、`assets/internal_original/mappings`、素材构建清单和多个代码
Catalog 中。后续重构目标是形成统一插件描述和注册入口；在迁移完成前，现有目录仍可作为物理存储，
但不得继续增加平行硬编码清单。

## 目标仓库结构

每份插件最终集中到一个所有权根目录，避免定义、素材和测试散落后产生双清单：

```text
src/kernel/contracts/          # 纯契约和稳定值对象
src/kernel/runtime/            # 插件发现、注册、冻结与宿主装配
plugins/base/
  plugin.json
  rules/
  world/
  combat/
  characters/
  builds/
  presentation/
  localization/
  tests/
plugins/th06_eosd/
  plugin.json
  ...同一目录契约...
```

插件构建产物可以由工具从该目录生成，但工具不能维护第二份人工清单。源码、资产来源、运行映射和
验收测试必须能从同一个插件身份追溯。

## 注册与开局流程

1. 启动时发现内置插件，并读取身份和 schema 版本。
2. 校验稳定 ID、依赖、资源路径、数值范围和跨作来源声明。
3. 先注册本体，再注册玩家勾选的可选插件。
4. 将各领域贡献合并为只读注册表，并检测重复 ID 与非法覆盖。
5. 生成本局 `RunContentContext`，记录启用插件、选中角色和世界种子。
6. 冻结注册表后进入世界；本局中途不加载、卸载或替换内容插件。
7. 图鉴可以查看所有已安装内容，战斗与升级池只能读取本局已启用内容。

## 本体的最小完整闭环

不勾选任何作品时，玩家必须能完成以下流程：

`主菜单 -> 选角色 -> 进入无限世界 -> 形成 Build -> 动态压力换档 -> 角色 Boss -> 成功或失败结算`

本体当前内容规模可作为第一轮基线，但“清单存在”不等于验收完成：

- 5 个地区、6 个结构和 9 类敌人必须在真实世界中产生可辨认的玩法差异。
- 灵梦与魔理沙都可作为自机和 Boss；当前自机必须从本局 Boss 候选中排除。
- 6 张本体奥义能够独立填满 `4 主攻 + 2 护持`，不依赖任何作品插件。
- 普通弹、中心弹幕、护身、机动、聚灵和奥义至少形成数条完整而等预算的 Build 路线。
- 动态压力只由三十秒滑动窗口的清场能力推动；怪物种类属性不随阶段偷偷增长。
- 死亡、成功、继续无尽、暂停返回、设置、图鉴、地图、音频和版本日志均可独立使用。

在本体闭环通过前，其他作品内容只作为已安装资料保留，不作为“游戏已完成”的证据。

## Build 的插件契约

每个 Build 节点在进入实现前必须写清以下内容：

1. **幻想与动作**：玩家实际看到什么、为什么符合东方与武侠语义。
2. **核心循环**：该节点改变瞄准、弹幕、走位、承伤、拾取还是触发条件。
3. **成长轨迹**：`A/B` 的当前重数与上限，通常上限为 2 至 4，满重后退出候选池。
4. **行为变化**：每一重具体改变数量、阵形、目标规则或状态，而不只写模糊百分比。
5. **数值预算**：单体、群体、生存或经济价值采用同一比较口径，插件身份不提供额外预算。
6. **自然协同**：通过通用标签与其他节点组合；地区和敌人可以让某套 Build 更好用，但不强制掉落。
7. **失败边界**：什么情况下较弱、有什么替代路线，避免出现全场景最优解。
8. **表现与可读性**：弹型、颜色、音效、命中特效和 E 状态页说明来自同一份定义。
9. **验收指标**：命中率、清场率、Boss 伤害、存活率和五分钟成型程度必须可以测量。

插件只能贡献遵守该契约的新节点或奥义，不能复制一个更高数值版本替代本体节点。

## 东方红魔乡：第一份参考插件

红魔乡的目的不是尽快增加内容量，而是证明插件契约能覆盖一份完整作品。第一轮范围固定为：

- 3 个地区：雾之湖、红魔馆领地、巴瓦鲁魔法图书馆。
- 3 个结构：雾湖小岛、红魔馆、大图书馆。
- 3 类地区敌人，并至少具有可分辨的移动、攻击或死亡行为。
- 7 个角色，同一身份同时支持自机与 Boss，本局继续排除当前自机。
- 7 张代表符卡，使用所属 BulletAtlas、几何和阶段演出，并遵守本体奥义预算。

参考插件必须实际验证以下扩展点：

- 地区改变生态与结构分布，但不改全局难度公式。
- 结构至少提供一种发现、遭遇或奖励语义，而不是地图上的彩色图标。
- 敌人行为通过注册的 AI 档案组合，不在 ECS 循环里判断 `th06_eosd`。
- Boss 通过角色与符卡定义装配招式，不在遭遇导演中硬编码角色名。
- 新 Build 和奥义只是横向候选；启用红魔乡前后，槽位、升级总类别权重和本体数值预算不变。
- 关闭红魔乡后进行同种子本体测试，不能留下任何红魔乡身份、资源或规则。

红魔乡通过上述验收后，它的目录、schema、注册器和测试模板才可以复制给下一部作品。

## 验收门槛

### 本体门槛

- Base-only 从开局到结算无缺项，不需要任何可选插件兜底。
- 所有 Build 都有完整设计卡、真实行为测试和五分钟时间轴验证。
- 内核源码和场景中不存在具体作品 ID。
- 删除本地可选插件目录后，本体仍可构建、启动、游玩和读取存档。

### 红魔乡门槛

- 单独启用和关闭都通过世界、战斗、图鉴、角色、Boss、奥义和素材隔离测试。
- 插件内容没有注册表冲突、中文名身份连接或静默跨作素材回退。
- 至少覆盖世界、结构、敌人 AI、角色、Boss 招式、Build 和表现七种扩展面。
- Base-only 与 Base+TH06 的通用成长预算相同；差异来自选择和组合，而不是纵向加成。

## 当前实施顺序

1. 冻结除 TH06 外所有可选作品的新增玩法开发，保留现有资料和素材清单。
2. 审计并补齐 Base-only 完整流程，逐套写清本体 Build 后再实现。
3. 抽出统一插件身份、注册表、依赖校验和只读运行上下文。
4. 把现有本体硬编码迁移为始终启用的 Base Plugin。
5. 把红魔乡迁移为首个 Optional Plugin，并完成隔离与横向平衡验收。
6. 只有 Base 与 TH06 模板稳定后，才按同一契约迁移其他作品。

这套顺序不会删除现有 DLC 资料；它只是停止用“目录里已经有名字”代替真实玩法完成度。

## 当前非目标

- 暂不提供下载第三方 DLL、执行不受信任代码或联网热更新的公开 Mod 平台。
- 暂不支持一局进行中安装、卸载或重载插件。
- 不为每个小类增加接口；只有跨插件变化的领域边界才形成契约。
- 不允许插件覆盖另一个插件的稳定 ID；兼容改动必须通过显式迁移完成。
- 不在插件契约稳定前继续批量制作除 TH06 外的作品玩法内容。
