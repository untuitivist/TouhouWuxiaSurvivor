# 插件化内核与内容包的产品基调

## 一句话定义

本项目的主基调是：**技术上一切皆插件，产品上作品只作为内容包。**

内核提供运行环境，必选规则模块定义统一玩法，内容包只注册具体内容。幻想乡本体是始终启用、
随游戏发行的基础内容包；东方红魔乡是第一份可关闭的参考内容包。本体必须独立构成完整游戏，
红魔乡只横向增加选择，不能替本体补齐缺失流程，也不能提供更高的数值上限。

## 插件与内容包不是同一个概念

插件是工程组织方式：具有稳定身份、明确所有权、统一契约和独立测试的模块。内容包是产品单位：
一组遵守既有玩法规则的地区、结构、敌人、角色、技能和表现。二者不能混称为 DLC。

- 系统能力通过内部模块组合，但不等于让每个类都成为可热加载 DLL。
- 地区、结构、敌人、角色、Build、奥义、Boss 招式、素材、音频和本地化都由所属内容包提供。
- 菜单、图鉴、地图、升级选择和状态页只读取注册后的统一视图，不按作品编号写分支。
- 高频 ECS 系统在开局前完成装配并冻结，战斗过程中不扫描目录、不使用反射，也不动态卸载模块。
- 低频界面和遭遇编排可以通过接口组合，但同样只能依赖契约，不能向具体作品反向取数据。
- 插件化的目标是隔离变化、保证横向扩展和便于测试，不是增加抽象层数量。
- 内容包若需要现有系统无法表达的新行为，必须先把它抽成所有内容都能使用的通用能力，再由
  内容包配置；禁止在通用系统中加入作品 ID 判断。

## ECS 与 OOP 的选择原则

“一切皆插件”不等于“一切皆 ECS”，也不等于继续用 Node 表示每颗弹丸。架构按数据规模和职责
选择，而不是按偏好统一技术：

| 判断维度 | 适合 ECS | 适合 OOP / Godot Node |
| --- | --- | --- |
| 数量 | 数十至数千个同构实例 | 少量有明确身份的对象 |
| 更新 | 每物理帧批量运行 | 事件驱动或低频轮询 |
| 生命周期 | 高频创建、回收、对象池 | 场景级、会话级或长期存在 |
| 行为 | 可拆成数据组件和纯系统 | 编排、状态机、界面交互和资源所有权 |
| 编辑器 | 不需要逐个编辑场景节点 | 需要 Godot 场景树、锚点、主题或音频节点 |

本项目的具体边界：

- 普通敌人、Boss 战斗实体、双方弹丸、掉落物、灵息、命中和高频状态使用 ECS。
- 主菜单、内容选择、暂停、图鉴、E 状态页、地图界面、音频控制和结算使用 OOP Node。
- 区块与结构由 OOP 负责低频生命周期和遭遇编排；真正进入战斗的守卫、Boss 与弹幕交给 ECS。
- Boss 导演是 OOP 编排器，Boss 的位置、生命、阶段战斗状态和投射物仍是 ECS 数据。
- 内容包加载、校验、注册和存档迁移属于 OOP 服务；冻结后的高频定义投影为 ECS 可直接读取的
  紧凑数据，战斗中不解析 JSON。

两侧通过命令、领域事件和不可变快照连接。OOP 不逐帧遍历 ECS 内部集合，ECS 不保存 UI Node、
场景节点或内容加载器引用。这样既保留 Godot 场景编辑效率，也避免高实体数量退化成 Node-per-entity。

## 四层边界

### 1. Kernel：游戏内核

内核拥有机制，不拥有东方内容：

- 游戏生命周期、输入、暂停、存档、随机种子和场景切换。
- ECS 存储、调度、碰撞、投射物预算和渲染提交。
- 无限世界坐标、区块流送、地图发现和结构实例生命周期。
- 插件发现、版本校验、依赖解析、注册表冻结和错误报告。
- 通用 UI 容器、音频总线、资源加载、图鉴投影和调试指标。

内核只负责调用“压力策略”“升级候选策略”“胜负策略”等契约，不定义五分钟、`K/S`、经验需求
或三选一权重。

内核中禁止出现 `th06_eosd`、蕾米莉亚、红魔馆等内容身份，也禁止按作品编号维护 `switch`。

### 2. Game Rules：必选玩法规则模块

规则模块定义所有内容包共同遵守的游戏：五分钟目标、动态压力换档、经验升级、三选一、槽位、
Boss 胜负与无尽延续。它们是内部插件化模块，但不是玩家可以勾选的内容包。

- 一次运行只选择一套完整 Run Mode，不能被内容包逐项篡改。
- 内容包不能改变经验公式、刷新公式、候选类别权重、槽位容量、输入或胜负条件。
- 将来若制作另一种玩法，应新增完整 Run Mode，而不是借某个作品内容包偷偷修改当前玩法。

### 3. Base Content Pack：幻想乡本体

本体使用与可选内容包相同的注册契约，但始终启用且不可在新局菜单中关闭。它提供一局游戏所需的
最小完整内容，而不是“公共素材垃圾桶”或其他内容包缺项的回退层。

本体可以公开少量稳定能力标签，例如普通攻击、中心弹幕、护身、聚灵和结构遭遇，供可选内容包
声明协同；可选内容包不能直接引用本体内部类、场景路径或中文显示名。

### 4. Optional Content Pack：作品内容包

每个作品内容包彼此平行，只依赖内容契约和本体公开能力，不依赖另一个可选作品。

- 启用内容包只增加候选和世界可能性，不修改全局经验、刷新、槽位或基础属性公式。
- 禁用内容包后，其地区、结构、敌人、角色、奥义、Boss、素材和图鉴条目必须全部消失。
- 内容包缺少某类内容时必须显式声明不可用，不能静默借用另一个作品并伪装成本作素材。
- 跨作复用必须记录来源、原因和审核状态；运行时身份仍属于消费方内容包。

## 依赖方向

```text
Game Host
  -> Kernel Contracts
       <- Mandatory Game Rule Modules
       <- Base Content Pack
       <- TH06 Content Pack
       <- Future Content Packs
```

允许的依赖只有指向契约。内核不依赖具体模块，可选内容包之间不互相依赖，Base 不知道有哪些
可选内容包。
角色、奥义或素材之间的关联使用稳定 ID 和能力标签解析，不使用中文名称连接对象。

## 内容包拥有的完整内容面

一份内容包不是单个 `pack.json`，而是以下内容的逻辑所有者：

| 领域 | 内容包必须拥有的定义 |
| --- | --- |
| 身份 | 内容包 ID、版本、依赖、兼容版本、显示名称、选择状态 |
| 世界 | 地区、地貌规则、结构模板、放置规则、发现与遭遇 |
| 战斗 | 普通敌人、强度档、AI 档案、掉落、Boss 档案与招式 |
| 角色 | 稳定角色 ID、自机档案、Boss 档案、起始倾向 |
| Build | 升级节点、重数上限、行为变化、亲和、奥义和协同标签 |
| 表现 | 纹理、弹幕图集、动画、音频、地图颜色和 UI 文本 |
| 兼容 | 存档迁移、缺失插件说明、素材来源和许可边界 |
| 验收 | 清单完整性、隔离、数值预算、真实运行和视觉测试 |

当前仓库把这些所有权分散在 `content`、`assets/internal_original/mappings`、素材构建清单和多个代码
Catalog 中。后续重构目标是形成统一内容包描述和模块注册入口；在迁移完成前，现有目录仍可作为
物理存储，但不得继续增加平行硬编码清单。

## 目标仓库结构

每份规则模块和内容包最终集中到自己的所有权根目录，避免定义、素材和测试散落后产生双清单：

```text
src/kernel/contracts/          # 纯契约和稳定值对象
src/kernel/runtime/            # 模块发现、注册、冻结与宿主装配
modules/rules/base_run/
  module.json
  pacing/
  progression/
  victory/
content_packs/base/
  pack.json
  world/
  combat/
  characters/
  builds/
  presentation/
  localization/
  tests/
content_packs/th06_eosd/
  pack.json
  ...同一目录契约...
```

构建产物可以由工具从该目录生成，但工具不能维护第二份人工清单。源码、资产来源、运行映射和
验收测试必须能从同一个模块或内容包身份追溯。

## 当前仓库与目标的断层

现有实现已经具备“按目录发现内容”的雏形，但还没有达到真正的数据所有权闭环：

| 当前入口 | 当前问题 | 目标状态 |
| --- | --- | --- |
| `ContentPackCatalog` | 能发现 `pack.json`，但多数内容只用于菜单说明 | 发现、校验并注册完整内容定义 |
| `ContentPackManifestLoader` | 将地区、结构、敌人、角色转换为显示文字 | 读取带 schema 的强类型索引，不负责领域实现 |
| `OfficialWorldContentCatalog` | 六十组世界内容集中硬编码在一个 C# Catalog | 世界定义归所属内容包，运行时只看 `BiomeRegistry` 与 `StructureRegistry` |
| `CharacterCatalog`、`EnemyCatalog` | 身份、数值和行为仍由全局代码拼装 | 内容包提供定义，通用工厂装配 ECS 组件 |
| `RunUpgradeCatalog`、`SpellCardCatalog` | 能按来源过滤，但定义仍跨 JSON 与代码分散 | Build 与奥义从同一内容定义注册，并使用通用行为能力 |
| `ContentPackIds` | 每增加作品都要修改全局常量 | 内容包 ID 来自清单，内核不枚举具体作品 |
| `RunContentContext` | 只记录启用集合、角色和种子的一部分语义 | 冻结规则版本、内容版本、指纹、角色与种子 |

当前还有少量 `th06_eosd` 直接引用存在于 Boss 招式和符卡表现链。迁移红魔乡时必须改成“定义中
引用稳定能力 ID 与素材 ID，由注册表解析”，不能把这些判断搬到另一个工具类里。

## 内容包清单契约 v1

`pack.json` 是内容包唯一人工入口，不再只是菜单摘要。建议目标结构如下；数组中的文件继续按领域
拆分，避免一个 JSON 膨胀为不可维护的大文件：

```json
{
  "schema_version": 1,
  "id": "th06_eosd",
  "content_version": "1.0.0",
  "host_api": "content-v1",
  "kind": "optional",
  "status": "development",
  "display": {
    "name_zh": "东方红魔乡",
    "description_zh": "雾之湖与红魔馆内容包"
  },
  "dependencies": {
    "required": ["base"],
    "optional": []
  },
  "definitions": {
    "biomes": ["world/biomes.json"],
    "structures": ["world/structures.json"],
    "enemies": ["combat/enemies.json"],
    "characters": ["characters/characters.json"],
    "builds": ["builds/upgrades.json"],
    "spell_cards": ["builds/spell_cards.json"]
  },
  "presentation": ["presentation/assets.json"],
  "localization": ["localization/zh_cn.json"],
  "provenance": "presentation/provenance.json"
}
```

清单规则如下：

- `schema_version` 表示文件结构版本；未知版本必须明确拒绝，不能猜字段。
- `content_version` 是内容包自身版本，不等于游戏发行版本；它用于存档兼容和缓存失效。
- `host_api` 表示该包依赖的内容契约版本，不能使用游戏版本字符串替代。
- `kind` 只能是 `foundation` 或 `optional`；一次发行必须且只能有一个基础包。
- `status` 只能是 `inventory`、`development` 或 `complete`；分别表示资料库存、正在开发验收和
  已通过完整契约，不能用“清单存在”自动推导完成。
- 可选包只能依赖基础包公开能力；第一阶段不允许可选包之间形成依赖链。
- `definitions` 只列领域定义文件，不直接列菜单用中文名称。
- `presentation` 与逻辑身份分离，同一个逻辑条目可以更换表现，但不能因此改变稳定 ID。
- `provenance` 对每项内部原作素材记录来源、许可边界、代理来源、原因和审核状态。

稳定 ID 使用 ASCII，并包含所属包和领域，例如 `th06_eosd:enemy:lake_fairy`。中文名、日文原名和
译名只属于本地化数据，不能参与存档、引用、互斥或 Boss 排除。迁移期间保留旧 ID 到新 ID 的显式
映射；已经进入存档的 ID 不得因改译名而变化。

## 强类型注册表

宿主不向内容包暴露整个场景树，只提供有限注册入口。目标注册表至少包括：

| 注册表 | 负责内容 | 主要消费者 |
| --- | --- | --- |
| `ContentPackRegistry` | 包身份、版本、依赖、指纹和安装状态 | 主菜单、存档、诊断 |
| `BiomeRegistry` | 地区身份、地貌、生态表和地图表现 | 世界生成、地图、图鉴 |
| `StructureRegistry` | 放置、模板、入口、遭遇和奖励插槽 | 结构生成、发现系统、地图 |
| `EnemyRegistry` | 固定物种属性、强度档、AI 与掉落 | 刷怪导演、ECS、图鉴 |
| `CharacterRegistry` | 自机档案、Boss 档案和表现 | 角色选择、玩家装配、Boss 导演 |
| `BuildRegistry` | 普通升级、重数、标签和行为参数 | 三选一、E 状态页、数值模拟 |
| `SpellCardRegistry` | 奥义触发、几何、效果和演出 | 三选一、自动施放、Boss 演出 |
| `PresentationRegistry` | 纹理、动画、音频、弹图和本地化键 | 渲染、音频、图鉴 |

注册过程遵守“先完整校验，再一次冻结”：

1. 发现所有已安装包，只读取身份头，不立刻注册领域内容。
2. 检查 schema、host API、依赖和内容指纹。
3. 解析所有强类型定义，并校验引用目标、单位、范围和枚举能力。
4. 检测全局稳定 ID 重复；任何内容包都不得覆盖既有定义。
5. 检查逻辑条目与表现、本地化、素材来源是否闭合。
6. 只有全部成功后才生成不可变注册表；任一步失败都不留下半注册状态。

图鉴读取“已安装注册表”，新一局读取“本局注册表”。这两者必须分开，否则玩家只安装但没有勾选
的内容会泄漏进刷怪、Boss 或升级池。

## 通用能力而非作品分支

内容包第一阶段只携带声明式数据和素材，不携带任意 C# DLL。所谓“一切皆插件”指内部能力模块
和内容所有权遵循契约，不等于允许数据包执行不受信任代码。

内容定义通过通用能力 ID 组合行为：

- 敌人组合移动、索敌、射击、突进、接触和死亡效果能力。
- 结构组合放置、地面模板、入口、守卫、Boss 场、奖励和发现能力。
- 普通升级组合数值维度、弹数、阵形、贯穿、吸附、护身和条件标签。
- 奥义组合触发、投送方式、几何、载荷、目标选择和演出。
- Boss 组合阶段条件、符卡序列、移动档案、弹幕图集和结算奖励。

如果红魔乡需要一种现有能力无法表达的行为，正确流程是：先在规则或通用战斗模块中增加一个
与作品无关、带预算和测试的新能力，再由红魔乡定义引用它。禁止写
`if (packId == "th06_eosd")`，也禁止用中文名暗中实现同样的分支。

## 注册与开局流程

1. 启动时发现必选规则模块和已安装内容包，并读取身份和 schema 版本。
2. 校验稳定 ID、依赖、资源路径、数值范围和跨作来源声明。
3. 先注册规则模块和本体，再注册玩家勾选的可选内容包。
4. 将各领域贡献合并为只读注册表，并检测重复 ID 与非法覆盖。
5. 生成本局 `RunContentContext`，记录启用内容包、选中角色和世界种子。
6. 冻结注册表后进入世界；本局中途不加载、卸载或替换规则模块与内容包。
7. 图鉴可以查看所有已安装内容，战斗与升级池只能读取本局已启用内容。

### 本局冻结快照

当前仅保存启用包 ID 不够。新的 `RunContentContext` 至少要固定：

```text
RuleSetId + RuleSetVersion
WorldSeed
SelectedCharacterId
EnabledPackId + ContentVersion + ContentFingerprint
RegistryFingerprint
```

规则模块使用这份快照创建地区池、结构池、敌人池、Boss 池和升级池。运行中菜单设置、磁盘文件或
图鉴状态都不能改变已经开始的一局。随机选择只能从冻结后的稳定排序集合采样，保证相同种子、
相同版本和相同内容组合能够复现。

`installed`、`enabled` 和 `active` 是三个不同状态：

- `installed`：磁盘中存在，可进入图鉴。
- `enabled`：玩家在新局前勾选，允许参与本局候选构建。
- `active`：经过依赖和兼容校验后，实际进入冻结注册表。

界面不得把“已安装”显示成“本局已启用”，加载失败的包也不得静默降级成启用状态。

## 各领域的数据边界

### 世界与地区

规则模块拥有宏域大小、区块尺寸、探索揭示和内容包之间的总体抽取方式。内容包拥有自己的地区
定义、内部地貌参数、生态标签、结构池和地图表现。

- 启用更多包会增加可能出现的地区，但不会扩大地图密度、提高经验或改变一局时长。
- 地区可以让近战、范围、机动等 Build 自然产生优劣，但只能通过公开标签和地形事实形成，不能
  直接给某作品技能加隐藏倍率。
- 同一世界种子在相同包组合下必须稳定；改变包组合允许世界不同，但不能污染其他存档。

### 结构

结构定义由 `PlacementProfile + Template + EncounterProfile + RewardProfile + Presentation` 组成。
内容包决定“这是红魔馆还是雾湖小岛”，规则模块决定发现、清理、冷却和奖励结算的共同语义。

- 放置必须使用结构自己的 salt、间距、群系条件和占地，不能所有结构共享同一概率网格。
- 结构实例必须拥有稳定实例 ID、旋转、变体、状态和发现记录。
- 结构可以提供守卫、Boss、奖励或路线选择，但不能修改全局升级规则。
- 地图只有在玩家进入发现半径后才显示名称和状态，不能以区块被加载代替玩家探索。

### 普通敌人与强敌

敌人定义拥有固定的物种属性、强度档、AI 档案、攻击档案、掉落和表现。刷新阶段只改变刷新总量
和不同强度档的构成，不对已经定义的怪物生命、速度、接触伤害或奖励乘时间系数。

- 同一种敌人在第一档和最后一档的基础属性完全相同。
- 后续若需要增幅怪，必须注册成可识别的新变体或修饰类型，并在图鉴与调试层明确显示。
- AI 通过通用行为组件装配；内容包只提供参数和组合，不向 ECS 主循环注入作品判断。
- 内容包新增敌人只增加刷新目录；总刷新率、三十秒滑动窗口和换档阈值仍由规则模块控制。

### 角色与 Boss

角色只有一个稳定 `CharacterDefinition`，其中分别引用自机档案和 Boss 档案。当前选择的自机仅在
本局 Boss 候选查询时按稳定角色 ID 排除，不能删除或修改角色的 Boss 身份。

- 自机档案负责基础生命、移动、攻击节奏、起始倾向和表现。
- Boss 档案负责固定属性、移动策略、阶段表和符卡序列。
- Boss 出现时机、胜利条件和继续无尽属于规则模块。
- 内容包可以增加 Boss 候选和符卡演出，但不能改变 Boss 倍率、遭遇次数或结算规则。

### Build 与奥义

普通升级与奥义都使用统一的 `BuildDefinition` 投影，来源包只决定可用性和图鉴归属，不参与强度
计算。规则模块固定以下内容：

- 每次候选的类别结构、无放回规则和倾向算法。
- `A/B` 重数语义、满重退出候选、奥义 `4 主攻 + 2 护持` 槽位。
- 普通攻击与中心弹幕共享数值、分别成长表现的原则。
- 五分钟成型速度、数值预算口径和无尽延续方式。

内容包只提供等预算的新选择：定义前置、重数、亲和标签、行为参数、符卡几何和表现。地区、结构
或敌人可以通过规则允许的标签让某条路线更适合当前局面，但内容包不能改候选总权重，也不能把
自己的技能设为更高稀有度对应更高强度。

### 表现、音频与本地化

逻辑系统只保存 `VisualId`、`AudioCueId` 和本地化 key，不保存具体纹理、路径或中文字符串。
表现注册表负责解析到最近邻纹理、ActorStrip、Portrait、BulletAtlas、BGM 和音效。

- 一个声明为完整的条目缺少必要表现时应在加载阶段失败，不在战斗中静默换成阴阳玉。
- 开发期文字回退必须显式标记为 unavailable，不能算作视觉完成。
- 跨作素材代理必须在来源清单和运行映射两侧一致，并在内部版本声明许可边界。
- 同一奥义的图鉴预览、玩家施放和 Boss 演出必须读取同一个表现定义。

## 内容平行而非纵向增量

“不影响玩法”不代表所有敌人和技能手感相同。内容当然会改变当局的战术环境，但不能改变规则
框架和可获得的总强度。具体约束是：

- Base-only、Base+TH06 和未来任意内容组合都拥有相同的槽位、升级类别概率和五分钟成长预算。
- 内容包增加十张奥义时，奥义类别在三选一中的总权重保持不变，只是类别内部候选更多。
- 内容包增加敌人时，全局每秒刷新目标不变，只在对应强度档内部增加物种选择。
- 内容包增加结构时，世界中的结构密度和奖励预算不变，只增加模板与遭遇类型。
- 内容包增加角色时，不提供额外局外属性；角色以等预算方式交换攻击、节奏、生存和机动。
- 不使用“拥有更多内容包就更容易填满槽位”的设计；本体本身必须覆盖每个必要类别。

因此内容包的价值来自重玩差异、原作主题、组合变化和表现，不来自数值上限或流程特权。

## 存档与兼容

局外存档使用稳定 ID 记录角色、图鉴、解锁和偏好，并同时保存内容包版本。兼容规则如下：

- 卸载可选内容包后，其局外记录保留为休眠数据；重新安装兼容版本后恢复，不能直接删除。
- 正在进行的存档若缺少原启用包，必须列出缺失包并拒绝静默续局；不能拿本体敌人或技能替换。
- 兼容更新通过显式 ID 迁移表处理；找不到迁移时保留原记录并报告，不猜测中文同名条目。
- 内容指纹改变但版本未改变属于打包错误，应在开发和诊断构建中明确报警。
- 基础包是存档必需依赖；基础包不兼容时只能走正式迁移，不能以关闭基础包解决。

## 内容包加载错误

错误必须对开发者和玩家都可定位：

| 错误 | 行为 |
| --- | --- |
| schema 或 host API 不支持 | 禁用该包，显示所需版本 |
| 必需依赖缺失 | 禁用该包，列出依赖链 |
| 稳定 ID 重复 | 整个注册失败，列出双方来源 |
| 引用能力或资源不存在 | 禁用该包，定位文件、条目和字段 |
| 数值非有限或超出契约 | 禁用该包，显示允许范围 |
| 素材代理声明不完整 | 内部构建失败，不允许标记 complete |

正式版本不能因一个可选包损坏而崩溃主菜单，但也不能假装该包成功加载。本体或必选规则模块损坏
则应停止进入游戏，并显示可以复制的错误报告。

## 本体的最小完整闭环

不勾选任何作品时，玩家必须能完成以下流程：

`主菜单 -> 选角色 -> 进入无限世界 -> 形成 Build -> 动态压力换档 -> 角色 Boss -> 成功或失败结算`

本体当前内容规模可作为第一轮基线，但“清单存在”不等于验收完成：

- 5 个地区、6 个结构和 9 类敌人必须在真实世界中产生可辨认的玩法差异。
- 灵梦与魔理沙都可作为自机和 Boss；当前自机必须从本局 Boss 候选中排除。
- 6 张本体奥义能够独立填满 `4 主攻 + 2 护持`，不依赖任何可选内容包。
- 普通弹、中心弹幕、护身、机动、聚灵和奥义至少形成数条完整而等预算的 Build 路线。
- 动态压力只由三十秒滑动窗口的清场能力推动；怪物种类属性不随阶段偷偷增长。
- 死亡、成功、继续无尽、暂停返回、设置、图鉴、地图、音频和版本日志均可独立使用。

在本体闭环通过前，其他作品内容只作为已安装资料保留，不作为“游戏已完成”的证据。

## Build 的内容契约

每个 Build 节点在进入实现前必须写清以下内容：

1. **幻想与动作**：玩家实际看到什么、为什么符合东方与武侠语义。
2. **核心循环**：该节点改变瞄准、弹幕、走位、承伤、拾取还是触发条件。
3. **成长轨迹**：`A/B` 的当前重数与上限，通常上限为 2 至 4，满重后退出候选池。
4. **行为变化**：每一重具体改变数量、阵形、目标规则或状态，而不只写模糊百分比。
5. **数值预算**：单体、群体、生存或经济价值采用同一比较口径，插件身份不提供额外预算。
6. **自然协同**：通过通用标签与其他节点组合；地区和敌人可以让某套 Build 更好用，但不强制掉落。
7. **失败边界**：什么情况下较弱、有什么替代路线，避免出现全场景最优解。
8. **表现与可读性**：弹型、颜色、音效、命中特效和 E 状态页说明来自同一份定义。
9. **验收指标**：命中率、清场率、Boss 伤害、存活率和五分钟成型程度必须可以测量。

内容包只能贡献遵守该契约的新节点或奥义，不能复制一个更高数值版本替代本体节点。

## 东方红魔乡：第一份参考内容包

红魔乡的目的不是尽快增加内容量，而是证明内容包契约能覆盖一份完整作品。第一轮范围固定为：

- 3 个地区：雾之湖、红魔馆领地、巴瓦鲁魔法图书馆。
- 3 个结构：雾湖小岛、红魔馆、大图书馆。
- 3 类地区敌人，并至少具有可分辨的移动、攻击或死亡行为。
- 7 个角色，同一身份同时支持自机与 Boss，本局继续排除当前自机。
- 7 张代表符卡，使用所属 BulletAtlas、几何和阶段演出，并遵守本体奥义预算。

参考内容包必须实际验证以下扩展点：

- 地区改变生态与结构分布，但不改全局难度公式。
- 结构至少提供一种发现、遭遇或奖励语义，而不是地图上的彩色图标。
- 敌人行为通过注册的 AI 档案组合，不在 ECS 循环里判断 `th06_eosd`。
- Boss 通过角色与符卡定义装配招式，不在遭遇导演中硬编码角色名。
- 新 Build 和奥义只是横向候选；启用红魔乡前后，槽位、升级总类别权重和本体数值预算不变。
- 关闭红魔乡后进行同种子本体测试，不能留下任何红魔乡身份、资源或规则。

红魔乡通过上述验收后，它的目录、schema、注册器和测试模板才可以复制给下一份内容包。

## Base 与 TH06 的首轮内容矩阵

数量只是最小覆盖，不是完成判定；每一项还必须通过运行时、差异性、平衡和表现验收。

| 领域 | Base 必需内容 | TH06 参考内容 | 共同规则 |
| --- | --- | --- | --- |
| 地区 | 5 个幻想乡基础地区 | 3 个红魔乡地区 | 使用同一宏域、探索和地图契约 |
| 结构 | 6 个基础结构 | 3 个作品结构 | 使用同一放置、发现、遭遇和奖励插槽 |
| 敌人 | 9 类基础敌人 | 3 类作品敌人 | 固定物种属性，统一强度档和 AI 能力 |
| 角色 | 灵梦、魔理沙 | 7 个登记角色 | 同一角色定义同时支持自机和 Boss |
| 奥义 | 精确覆盖 4 主攻 + 2 护持 | 7 张代表符卡 | 相同槽位、预算、触发与表现契约 |
| Boss 演出 | 两名基础角色的招式序列 | 七名角色各自代表符卡 | 同一 Boss 阶段系统，不增加作品专用规则 |
| 表现 | 本体可独立显示全部内容 | 红魔乡使用所属原作素材 | 同一逻辑 ID 贯通图鉴、局内和 Boss 演出 |

Base 的条目要覆盖全部必要能力类别，TH06 只能提供替代和新组合。例如本体必须已经有追踪、直线、
中心弹幕、范围和护持；红魔乡可以用不同几何、触发与主题重新组合，不能因为启用它才第一次获得
某个必需槽位或基本求生手段。

## 验收门槛

### 本体门槛

- Base-only 从开局到结算无缺项，不需要任何可选内容包兜底。
- 所有 Build 都有完整设计卡、真实行为测试和五分钟时间轴验证。
- 内核源码和场景中不存在具体作品 ID。
- 在隔离夹具中不加载任何可选内容包时，本体仍可构建、启动、游玩和读取存档。

### 红魔乡门槛

- 单独启用和关闭都通过世界、战斗、图鉴、角色、Boss、奥义和素材隔离测试。
- 内容包没有注册表冲突、中文名身份连接或静默跨作素材回退。
- 至少覆盖世界、结构、敌人 AI、角色、Boss 招式、Build 和表现七种扩展面。
- Base-only 与 Base+TH06 的通用成长预算相同；差异来自选择和组合，而不是纵向加成。

## 从当前仓库迁移的执行顺序

迁移采用“建立新真源、逐域对照、切换消费者”的方式，不一次性移动全部文件，也不长期保留两个
可人工编辑的真源。

### 阶段 1：冻结范围并建立契约

1. 冻结 TH07 至 TH20 的玩法新增；原 JSON、素材和图鉴映射继续保留为迁移库存。
2. 为内容清单增加 schema、内容版本、host API、领域文件索引和来源索引。
3. 新增只读注册表、统一验证报告和 `RunContentContext` 快照。
4. 建立临时对照测试：新注册表投影必须与当前 Base/TH06 Catalog 的稳定 ID 和数量一致。

### 阶段 2：先迁移 Base

1. 将本体地区和结构从全局 `OfficialWorldContentCatalog` 迁入 Base 世界定义。
2. 将本体敌人、AI 引用和掉落迁入 Base 战斗定义。
3. 将灵梦、魔理沙的自机与 Boss 档案迁入 Base 角色定义。
4. 将本体普通升级和六张奥义迁入 Base Build 定义。
5. 将局内、图鉴、地图和素材消费者切到注册表；Base-only 全流程通过后停止读取旧 Base 清单。

### 阶段 3：把规则从内容中抽离

1. 将五分钟流程、滑动窗口压力、刷新档、升级候选、槽位和结算收口到必选规则模块。
2. 删除领域代码对 `ContentPackIds` 的依赖，改为读取冻结内容身份和标签。
3. 让刷新、Boss、Build 和地图只消费注册表接口，不扫描目录，也不持有 JSON 节点。
4. 用 Base-only 时间轴确认抽离前后刷新、升级、伤害和结算没有意外漂移。

### 阶段 4：迁移 TH06 作为实验

1. 按 Base 模板迁移 TH06 的地区、结构、敌人、角色、奥义和表现。
2. 把 Boss 招式、符卡效果和弹丸表现中的 `th06_eosd` 直接引用改为定义引用。
3. 对任何 TH06 新机制先增加通用能力，再由 TH06 参数化使用。
4. 完成 Base-only、Base+TH06、启用后再禁用三组隔离与确定性测试。

### 阶段 5：收敛旧路径

1. 确认 Base 与 TH06 所有消费者都已切换，旧 Catalog 只剩其他作品库存。
2. 为其余作品生成迁移报告，不自动把“有名字”提升为 complete。
3. 待用户确认具体文件清单后，才删除被新真源完全替代的旧定义和兼容入口。
4. 模板稳定后逐个迁移其他内容包，不并行批量复制尚未验证的设计。

这套顺序不会删除现有内容包资料；它先证明本体闭环和红魔乡隔离，再收缩平行硬编码。

## 自动验收矩阵

目标测试不只检查“目录里有多少条”，而要验证以下契约：

| 测试组 | 必须证明的行为 |
| --- | --- |
| Manifest | schema、版本、依赖、稳定 ID、字段范围和 UTF-8 合法 |
| Registry | 重复 ID、悬空引用、半注册和非法覆盖都会失败 |
| Base-only | 不启用任何可选包仍可选角色、成型、打 Boss、结算和无尽 |
| Isolation | 关闭 TH06 后，世界、敌人、角色、奥义、Boss、素材和图鉴运行池零泄漏 |
| Determinism | 相同规则、包版本、指纹、角色和种子产生相同注册排序与世界结果 |
| Balance | Base-only 与 Base+TH06 的槽位、类别权重、五分钟预算和怪群供给一致 |
| Runtime | 每类内容至少在正式 WorldDemo 路径生成或施放一次，不用旧 Actor 假覆盖 |
| Presentation | 图鉴、局内、自机/Boss 和地图读取同一表现 ID，缺图不静默回退 |
| Save | 缺包、升级、改译名和 ID 迁移都有明确恢复或拒绝路径 |
| Source policy | 内核和规则模块不出现具体作品 ID，C# 文件继续满足单类与 250 行约束 |

“临时移除可选内容包”的自动测试应在隔离测试夹具或独立导出目录中完成，不直接删除工作区源文件。

## 当前非目标

- 暂不提供下载第三方 DLL、执行不受信任代码或联网热更新的公开 Mod 平台。
- 暂不支持一局进行中安装、卸载或重载规则模块与内容包。
- 不为每个小类增加接口；只有跨模块变化的领域边界才形成契约。
- 不允许内容包覆盖另一个内容包的稳定 ID；兼容改动必须通过显式迁移完成。
- 不在内容包契约稳定前继续批量制作除 TH06 外的作品内容。
